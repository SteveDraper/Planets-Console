# Shell analytic registration is a sibling of the map fetch/merge registry

The SPA already has a deep map fetch/merge plugin table (`mapAnalyticRegistry`). Custom sidebar tiles, MainArea table views, query-param adapters, GameInfo availability, and table-stream hooks still branch on analytic id in `App`, `AnalyticsBar`, `MainArea`, and `bff.ts`. Those chrome concerns become a sparse **shell analytic registration** keyed by **turn analytic catalog** id -- not a second catalog, and not new slots on the map registry.

**Considered:** one mega SPA registry (map fetch, paint, sidebar, table, params, stream) -- rejected because map-only and table-only analytics do not share a consumer, and map paint ([#383](https://github.com/SteveDraper/Planets-Console/issues/383)) should not wait on shell chrome. Extending `mapAnalyticRegistry` with empty map mergers for table-only analytics (e.g. scores) -- coherent, but declined for this ticket so `#383` can extend the map registry without taking on Shell slots. Stream lifetime stays a slot on the shell registration ([ADR 0011](0011-fleet-stream-behind-table-and-map.md)); Core/BFF stream adapter registration stays [#384](https://github.com/SteveDraper/Planets-Console/issues/384).

**Consequences:** Adding custom SPA chrome is a module under `src/analytics/<id>/` plus one entry in the shell registry. Omit the registration for generic checkbox and generic table. Mode greying stays catalog `supports_table` / `supports_map`; GameInfo inactivity is a separate availability slot. Map fetch/merge (and later paint) stay on the map registry.
